CSE 111 Proposal for a Student Chosen Program

    (This is a proposal. All proposals are written with our best
    knowledge at the beginning of a project. As we progress from the
    beginning to the end of a project, we gain more knowledge, and we
    change some of our proposed ideas. This is part of completing any
    project and is fine.  However, we still must write a proposal so
    that our teachers or supervisors know what we intend to do. Please
    answer each of the following questions to the best of your

1. What is the title of your program?
    Secure and Interactive Python Banking Simulation (SIBS).

2. What real-world problem will your program address or help to solve?
    This program aims to develop a comprehensive command-line-based banking
    simulation application using Python. It addresses the real-world problem 
    of demonstrating core banking functionalities in a simplified, yet secure and 
    interactive, environment. Many individuals, especially students or those new to financial 
    concepts, benefit from a hands-on, risk-free platform to understand how bank accounts 
    operate, including deposits, withdrawals, transfers, account management, and even loan
    applications. This simulation provides a practical and engaging way to learn about personal 
    finance management and the underlying logic of banking systems, without the complexity or 
    security risks of real-world financial transactions

3. What will you learn from developing this program?
•	Understanding Core Banking Operations: Gain a deep understanding 
    of how fundamental banking services (deposits, withdrawals, transfers, account creation)
    are logically processed.
•	Data Persistence: Learn to implement data storage and retrieval using JSON files for user 
    accounts and transaction history, simulating a database.
•	Modular Programming: Develop skills in breaking down a complex application into
    smaller, manageable functions and modules for improved organization and reusability.  
•	User Input and Validation: Master techniques for handling various types of user 
    input, including numeric and string data, and implementing robust validation to prevent errors. 
•	Security Concepts: Explore basic security measures such as password 
    hashing (though not fully implemented, concepts of hashing are implied for robust systems), OTP
    generation, and payment passcodes.
•	Dynamic Feature Implementation: Understand how to implement dynamic features like currency
    conversion and a tiered loan limit system based on user activity.
•	Interactive User Interface: Create an engaging and user-friendly command-line interface 
    with clear menus and feedback messages.  
•	External Communication Simulation: Learn to simulate external communications like email 
    and SMS notifications for transactions and account activities.

4. What Python modules will your program use?

    (Some examples are: csv, datetime, functools, matplotlib, math,
    pandas, pytest, random, requests, and tkinter.)
•	json: For reading from and writing to JSON files, serving as the primary data storage
    mechanism for user accounts and transactions.
•	datetime: For handling dates and times, essential for transaction timestamps, loan due
    dates, OTP expiry, and account age calculations.
•	random: For generating random numbers, crucial for OTP generation, reference numbers, and 
    potentially other simulated elements.
•	re: For regular expressions, used in input validation (e.g., email format, phone numbers).
•	hashlib: (Anticipated for future security enhancements) For hashing passwords or sensitive data.
